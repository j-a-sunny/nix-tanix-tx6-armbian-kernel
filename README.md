# nix-tanix-tx6-armbian-kernel

A Nix flake that packages **Armbian's prebuilt kernel, device tree, and
headers for the Tanix TX6** (Allwinner H6) as a proper, pinned, reproducible
Nix derivation — kept up to date automatically via GitHub Actions.

> **Built with heavy AI assistance.** The diagnosis of why this board's
> Ethernet doesn't work on stock kernels, the Nix packaging approach, the
> update tooling, and this README were all worked out interactively with
> Claude (Anthropic), not from prior kernel/Nix-internals expertise. It's
> been tested and verified working on real hardware, but read the code
> rather than just trusting it blindly — corrections welcome.

## Why this exists

The TX6's onboard Ethernet is wired through an **AC200** co-packaged chip
acting as the RMII PHY for the H6's EMAC. Driver support for it was written
around 2019 but **never merged into mainline Linux** — so any distro using
a stock/mainline-based kernel (including plain NixOS) has no way to bring
the board's Ethernet up. Armbian's build for this board carries the
necessary patches and is tested working; this flake repackages Armbian's
**already-built binaries** rather than compiling a kernel from source
(which is painfully slow on the H6 itself, and awkward to cross-compile
correctly).

## What's in here

| File | Purpose |
|---|---|
| `flake.nix` | Entry point — exposes the kernel as a package, an overlay, and a reusable NixOS module. |
| `armbian-kernel.nix` | The actual derivation. Fetches four `.deb`s (image, dtb, headers, libc-dev) via pinned `fetchurl`, extracts them with `dpkg-deb`, and lays them out the way NixOS expects (`Image`, `dtbs/`, `lib/modules/<version>/`, plus a `dev` output for headers). |
| `sources.nix` | The pins — URLs and sha256 hashes for the current build. Regenerated by the update script, not hand-edited. |
| `update-sources.sh` | Checks Armbian's repo for the newest build and rewrites `sources.nix`. Touches nothing else — no system files, no `/boot`. |
| `.github/workflows/auto-update.yml` | Runs the update script daily, verifies the new pin actually builds, and commits `sources.nix` if it changed. |

This repo is deliberately **just the kernel** — it doesn't include a full
`configuration.nix` or `hardware-configuration.nix`. Pair it with your own
system config (see [Usage](#usage) below).

## How it differs from compiling-from-source flakes (e.g. CachyOS kernels)

Projects like [nix-cachyos-kernel](https://github.com/xddxdd/nix-cachyos-kernel)
follow the same *shape* (pinned sources + an update script + CI) but
actually **compile** a kernel from source using nixpkgs' `buildLinux`. This
repo doesn't compile anything — `armbian-kernel.nix`'s build phase is just
`dpkg-deb -x` and `cp`, extracting binaries Armbian already built and
tested. Two practical consequences:

- **No QEMU/cross-compilation needed in CI.** Since nothing is actually
  compiled for aarch64, the update/verify workflow runs fine on a plain
  `ubuntu-latest` (x86_64) runner.
- **You inherit Armbian's kernel exactly as they ship it.** No custom
  config options, no local patch stack to maintain — if something's wrong
  with the kernel itself, it's wrong upstream in Armbian too, which is
  usually the right place for that problem to live.

## Usage

### As a flake input in your own NixOS config

```nix
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-26.05";
    tanix-tx6-kernel.url = "github:<you>/nix-tanix-tx6-armbian-kernel";
  };

  outputs = { self, nixpkgs, tanix-tx6-kernel, ... }: {
    nixosConfigurations.tanix-tx6 = nixpkgs.lib.nixosSystem {
      system = "aarch64-linux";
      modules = [
        tanix-tx6-kernel.nixosModules.default
        ./configuration.nix
        ./hardware-configuration.nix
      ];
    };
  };
}
```

That module sets `boot.kernelPackages`, the device tree, and the two
`boot.initrd.*` settings this kernel needs (see
[Known limitations](#known-limitations)) — you don't need to configure
those yourself.

### Standalone

```bash
nix build .#armbian-kernel-tanix-tx6
result/Image                    # the kernel
result/dtbs/allwinner/sun50i-h6-tanix-tx6.dtb
result-dev/lib/modules/*/build  # headers, for DKMS/out-of-tree modules
```

### Checking for updates yourself

```bash
nix run .#update-sources        # rewrites sources.nix if something newer exists
git diff sources.nix
git add sources.nix && git commit -m "Update Armbian kernel pin"
```

By default this tracks Armbian's `current` branch. To track `edge` instead:
```bash
BRANCH=edge nix run .#update-sources
```
(or change the default in `update-sources.sh`)

## Automatic updates

`.github/workflows/auto-update.yml` runs daily (and on manual dispatch):
checks Armbian's repo, and if a newer build exists, **builds it first to
confirm the pin is actually correct**, then commits `sources.nix` only if
that build succeeds. A broken/incomplete upstream release won't silently
land in your repo — the workflow just does nothing that day if the build
fails.

This intentionally does **not** auto-merge into your running system —
`sources.nix` gets updated in this repo; your NixOS config still only picks
up the new kernel the next time *you* run `nixos-rebuild`, same as any
other flake input bump.

## Known limitations

- **Scripted initrd, not systemd-stage-1.** This kernel doesn't go through
  nixpkgs' normal kernel-build machinery, so it lacks the parsed Kconfig
  object `boot.initrd.systemd.enable`'s initrd module wants to inspect.
  The `nixosModules.default` sets `boot.initrd.systemd.enable = false;` to
  route around this. Scripted initrd works fine; it's just slated for
  eventual removal upstream in NixOS.
- **`boot.initrd.includeDefaultModules = false;`** — NixOS's default
  initrd module set includes x86-oriented drivers (`ahci`, `ata_piix`,
  etc.) that don't exist in Armbian's ARM-only build. eMMC/SD support is
  compiled directly into the kernel here (not a loadable module), so
  nothing needs to replace this.
- **Audio not included.** The AC200 chip also has a codec side; this
  packages the Ethernet/EPHY-relevant kernel only (though the DTB does
  include the codec nodes — audio should Just Work if you enable it in
  your own config, untested here).
- **Repo layout may drift.** Armbian currently serves beta-branch packages
  under `dists/sid/main/binary-arm64/`. If that path changes, update
  `PACKAGES_PATH` in `update-sources.sh`.
- **Tanix TX6 specifically.** The dtb path (`sun50i-h6-tanix-tx6.dtb`) is
  hardcoded for this exact board. Other AC200-equipped H6 boards (Pine H64,
  Orange Pi 3, Tanix TX6-mini) would need `armbian-kernel.nix`'s dtb copy
  line adjusted, though the kernel/headers portion should be identical.
